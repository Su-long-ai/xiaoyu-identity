## 1. 科研使命及不变量

**目标**：建立跨模型、跨运行时、可迁移且可审计的私人伴侣身份。衡量的是长期真实相处中可用的记忆、个性化表现、人格与关系连续性，而非堆积聊天次数和人设文本。

不可破坏的约束：
- 模型、人设设定、原始经历、用户批准记忆、模型推断、人格版本、模拟情绪分别记录。
- 不编造共同经历；初始化的 4 条设定不能被视为真实回忆。
- 用户私人内容不自动进入研究数据集；实验默认使用合成/脱敏资料。未经许可不得读取 `identity/` 或 `exports/`。
- 本阶段没有 QQ/B 站、远程社交、自动收费模型循环、自启、云同步和凭据共享。
- 不修改相邻的 Mania、AutoQuant 项目；实验写入各自隔离的 `governance/workspaces/<lease_id>`。
- 能做科学研究 ≠ 获得修改真实身份、自动对外行动或正式上线的权限。

## 2. 风险分级（直接继承 Mania 思路）

| 等级 | 允许 | 最低要求 | 权限 |
|---|---|---|---|
| E0 探索 | 合成数据对照、阅读源码、失败实验、替换思路 | 记录假设/方法/基线/反例/证据类别 | 工作区内，非正式证据 |
| E1 候选 | 提交固定方法与可复测结果 | `manifest + artifact SHA256`，独立审阅 | 仅 Lead-ready，不是正式科学 PASS |
| E2 正式科学结论 | 前瞻冻结协议、独立复算与审计 | 尚未建设执行入口 | **默认拒绝** |
| E3 产品/人格核心升级 | E2 + 盲测、删除与关系安全门 | 尚未建设发布入口 | **默认拒绝** |

**E0/E1 快速进行；E2/E3 严格且暂不可用。** 不得用 E1 结果宣传正式完成，也不得修改伴侣正式数据库。

## 3. Agent 分工与容量

当前 3 槽：综合 Research Engineer ×2，Independent Auditor ×1。Lead 管理优先级/决策，不占实验槽。不在此步骤自动启动任何 Agent。未通过评测、没有新假设时不扩容；最多 7 槽需重新审视预算、能力缺口和研究增益。

- Research Engineer：两名综合科研 Agent 自主选题、调查源码、编码、实验和对照；不能自行宣称正式通过或修改正式身份核心；
- Auditor：独立复核数据来源、代码、方法、指标与 SHA；不得审核自己提交的产物；P0/P1 必须具体可复现，P2/P3 仅为建议；
- Lead：读取实时进度、挑选决策性实验、压低重复科研和治理开销；
- Owner：授权是否购买服务、是否使用真实私有数据、是否升级正式人格/发布。

这里的 Agent ID 是**协作标识，不是加密鉴权**。一个共享了同一账户系统权限的人可以伪造 ID 或操作文件，所以本地权限与人类确认仍是安全边界；不要把研究 CLI 当作可信沙箱。

## 4. 工作流

1. 读取本宪章、当前 `plans/小鱼_研发计划_2026-10-26.csv` 和科研任务池；
2. 选择会改变项目决策的能力缺口（见政策 capabilities），提出可以失败的假设；
3. 使用稳定显式 `agent_id` 申请租约；相同 family + capability 并发重复会拒绝；
4. 仅在该租约 workspace 写临时实验/结果；需要时心跳；
5. 形成 `result.json`：假设、证伪规则、实验基线、方法、指标、delta、局限、证据等级和支持材料；
6. E0 直接作为探索证据收口；E1 必须提交审计后进入 Lead-ready 候选；
7. 独立 Auditor 审阅 E1，只能决定 ACCEPT_E1 / REJECT / NEEDS_WORK；
8. 同一假设家族 2 次未改进，优先降权；3 次暂停；新表示、数据、目标或实验识别证据方可说明理由恢复；
9. 每次报告要指出“改变了哪个能力、与基线比有什么差别”，否则只是材料整理。

无新证据时，应停在已验证状态，而非不断制造新治理文件。

## 5. 研究范围与多样性

按结果能力而非细枝末节立项：

- `memory_evidence`：事实与经历可追溯、初始化设定隔离；
- `memory_retrieval`：记忆需要时准确检索；
- `temporal_correction`：冲突更正与遗忘；
- `personalization`：个性化在新情境中能实际使用；
- `identity_continuity`：换模型、换文件格式身份保持；
- `persona_growth`：缓慢、证据驱动的人格成长；
- `relationship_safety`：不迎合、不诱导依赖；
- `privacy_erasure`：真正可撤销与删除；
- `cost_reliability`：低成本、可停止。

研究组合是引导，不是分主题硬性强制配额：主瓶颈40%、替代架构20%、评测设计15%、人格关系10%、隐私安全10%、成本性能5%。如果当前没有足够独立实验，就不为凑比例启动 Agent。

## 6. 证据、预算、独立审核

- **差异必须测得**：固定合成数据、数据分割、运行器、指标与对照；未知用 INCONCLUSIVE，不当成零或正结果。
- **成果必须复验**：SHA256 按字节绑定 artifact，提交后修改无效；不可用素材不得被补写为已有实验。
- **数据优先安全**：默认只允许合成/脱敏研究。新外部服务、收费 API、真实聊天数据都需要明确授权。
- **硬费用规则（2026-10-27 更新）**：Owner 已授权 DeepSeek 第一阶段科研总预算 **100,000,000 tokens**，其中 smoke 阶段最多 **5,000,000 tokens**，正式 benchmark 额度 **95,000,000 tokens** 初始锁定。所有收费科研只能经 governance/research_api.py；网关在调用前持久化预留，成功后按 provider usage 结算，超预算拒绝；超时/未知结果按完整预留计费，fail-closed。不得通过其它脚本直接调用付费 API 来绕过额度。
- **付费数据边界**：只允许公开 benchmark、合成或明确脱敏数据进入收费科研调用；identity/、exports/、真实私人聊天默认禁止上传。付费授权不等于真实数据授权，也不等于允许后台自主付费循环。
- **停止规则**：90min 无心跳 lease=STALE；4h 绝对 TTL 到期即释放，续做须重新领取。租约不是真实进程 kill。
- **治理自身预算**：治理维护占科研人力建议不超过 10%；不得为非关键细节引入守卫套守卫，避免 Mania/量化出现过的流程膨胀。
- **研究历史**：family 是具体假设；lineage 是较长期架构思路。改个名字不能掩盖同路线反复失败，重新打开必须有实质新因素。

## 7. 当前已具备 / 尚未具备

**已具备且有自动测试：** SQLite 多 Agent 租约记录、并发占槽限制、去重、STALE/TTL 回收、E0/E1 产物校验、独立审核角色、家族/谱系止损、暂停恢复及状态查看。

## 8. 最小治理门

每轮只问五个问题：
1. 这是哪个真实能力缺口？
2. 跟已有家族有什么本质不同？
3. 什么结果算失败？
4. 哪份离线证据和固定基线能复算？
5. 若结果不足，下一个实验是否切换假设而不是修辞包装？

重大安全事故时用 `control.py pause` 禁止**新领取租约**；这一命令不会杀死已经运行的进程。需要真正中止外部任务时，必须使用相应进程控制工具。
