# XiaoYu Private Overlay

This directory is the permanent private customization layer on top of Project N.E.K.O.

Principles:
- N.E.K.O remains the product chassis and the single runtime authority for memory, persona storage, persona evolution/evidence promotion, tasks, voice/vision and plugin/tool execution.
- QQ is reused through the pinned external N.E.K.O QQ plugin and N.E.K.O OneBot/QQ connectors.
- XiaoYu owns only private identity constraints/content, provider trust policy, conformance tests, one-time legacy migration and narrowly-scoped adapters proven necessary by a failing product test.
- Growth mechanics are not implemented in the overlay. N.E.K.O native evidence/reflection/persona-promotion/correction mechanisms remain authoritative; XiaoYu only declares which identity dimensions may or may not change.
- Private runtime plugins are exception-only. The current xiaoyu_interaction_policy adapter exists because a live object-less quiet request was obeyed only conversationally while native proactive delivery stayed enabled; it performs semantic intent mediation only and delegates hard execution to N.E.K.O's built-in proactive_controller.
- Do not modify N.E.K.O core unless a wanted feature cannot be expressed as configuration, external component, plugin or adapter.
- Core patches live only in patches/ and are explicitly counted. The current budget is ten narrow patches, each admitted only after a reproduced live product gap and tied to acceptance evidence.
- Never dual-write memory/identity authorities.
- Private customization is optimized for this user, not for upstream generality.

Development layout:
- N.E.K.O checkout: D:\xiaoyu_external_audit\N.E.K.O
- private overlay checkout: this repository
- isolated private state: D:\xiaoyu_private_overlay_state
- pinned external QQ plugin: private_overlay/QQ_PLUGIN_UPSTREAM.lock.json
- pinned official desktop host: private_overlay/DESKTOP_SHELL.lock.json

Startup:
- Run tools/setup_local.ps1 after changing pinned external components.
- Use tools/start_xiaoyu.ps1 for backend-only/private-runtime startup. It verifies local pins, ensures the pinned native embedding profile before launcher startup, repairs a missing pinned steamworks sparse package through the existing setup workflow, completes N.E.K.O's native first-run storage selection when needed, verifies or upgrades the private interaction plugin through N.E.K.O's own package/install transaction, enforces the native activity preference work_break_game_invite_probability=0.0 so focused-work break reminders never pivot into a mini-game, runs the privacy/authority preflight, sets the isolated XiaoYu storage root, and launches N.E.K.O directly. XiaoYu also sets N.E.K.O's native NEKO_CLOUDSAVE_DISABLED session fence because this private local root is the storage authority; this prevents Steam Auto-Cloud import/export without replacing Steamworks itself. `-PreflightOnly` performs only fail-closed validation and never repairs sparse assets, rewrites activity preferences, or upgrades the plugin.
- Use tools/start_xiaoyu_oneclick.ps1 for normal daily use. When the existing QQ plugin is configured for a local napcat_forward endpoint, the launcher first reuses the installed NapCatQQ Desktop process if that OneBot endpoint is not already reachable; it never stores QQ credentials or implements login itself, and a still-unready OneBot endpoint is surfaced as a bounded "NapCat/QQ login required" notice. The launcher then waits until the XiaoYu main/memory/agent services are healthy and launches the pinned official N.E.K.O desktop host so the existing XiaoYu backend is shown as a desktop pet instead of opening a browser.
- Use tools/start_xiaoyu.ps1 -PreflightOnly to validate the backend launch path without starting the UI.
- Run `tools/install_xiaoyu_shortcuts.ps1` after moving or re-cloning the overlay. It recreates the `小鱼 XiaoYu` one-click launcher, the debug shortcut for `http://127.0.0.1:48911/`, and the local API-cost shortcut from the current checkout path instead of preserving stale workspace paths.

The desired steady state is data + policy + conformance around N.E.K.O, not a second XiaoYu runtime.

## Native identity/persona authority

identity/persona.md is a data-only private identity seed, not a runtime persona database. Runtime persona authority remains N.E.K.O's native memory/XiaoYu/persona.json and its evidence/reflection/correction/archive machinery. migration/seed_native_persona.py defaults to verify-only, extracts only explicitly admitted identity/growth/non-goal bullets, and on --commit sends them through N.E.K.O's existing live external-memory persona fusion so token budgets, contradiction checks, CAS, atomic save and folded-fingerprint idempotence remain native. Engineering constraints and character-card-owned fields are not imported as persona facts.

Stale persona facts are never fixed by editing persona.json directly. migration/retire_stale_persona.py is fail-closed while N.E.K.O is running and, in a controlled maintenance window, delegates retirement to native PersonaManager.aarchive_persona_entry, preserving the event log and archive shard for replay/recovery. The 2026-11-21 cutover retired the legacy “刚开始认识彼此” assertion after the continuity seed established that XiaoYu is one continuing companion across model/provider/restart/surface changes.

## Private interaction-policy adapter

plugins/xiaoyu_interaction_policy is a narrow private plugin, not a second agent/runtime authority. Text interaction controls now consume N.E.K.O's native conversations_v2 watcher (XiaoYu user text only) instead of polling the memory bus every second; voice controls continue to use the native voice_transcript_observed event. A 30-second reconcile timer remains only for bounded-quiet expiry, watcher recovery and a bounded conversations_v2 incremental fallback. The resulting plugin capability is conversations.read; the old memory.read polling dependency is removed. The plugin asks the configured Qwen classifier only for candidate semantic controls, delegates hard proactive state changes to proactive_controller, and writes screen privacy through native conversation settings. XiaoYu v0.6+ has one durable reply-output authority: quiet. When quiet is active, the opt-in N.E.K.O gate suppresses the whole assistant reply before the UI/TTS split; when a reply is admitted, text stays paired with TTS. The legacy speech_muted field is compatibility-only and normalized to false. Exact short commands keep a synchronous current-turn fast path solely to close classifier latency. Persisted private state contains only control state, timestamps/high-water cursors and event IDs for deduplication; it does not persist user message text. Recent desktop-activity recall delegates to ActivityWatch as the external local authority, returning only application names, AFK-filtered durations and explicit coverage; missing coverage remains UNKNOWN. The same plugin now exposes an agent-hidden interruptibility_v1 entry as an evidence-only shadow provider. Core discovery/execution reuses N.E.K.O's existing PluginCatalog and PluginRunner; there is no private plugin registry or second broker. The shadow provider currently always abstains and cannot weaken or delay the native Windows/ActivitySnapshot veto. N.E.K.O's User Plugin relay is enabled while the Agent master/analyzer, Computer Use and Browser Use remain disabled. N.E.K.O plugin startup recovery is also host-driven: the source-launch adapter only calls the native registry refresh/start APIs for host-declared approved auto-start plugins and restores the independent User Plugin relay; it no longer scans manifests, computes dependency order, or owns plugin processes.


## Native hybrid-memory assets

XiaoYu uses N.E.K.O's existing local embedding and hybrid-recall stack; the overlay does not own a vector store, embedding worker, model runtime, or downloader. The source checkout needs the same pinned model assets that N.E.K.O's official desktop build prepares: profile local-text-retrieval-v1 from jinaai/jina-embeddings-v5-text-nano-retrieval at commit ac5d898c8d382b17167c33e5c8af644a3519b47d. On this machine N.E.K.O's native hardware resolver selects int8.

tools/ensure_native_embedding_assets.py is only an asset/pin adapter. With a complete matching profile it returns without spawning a downloader; when assets are missing it delegates byte acquisition and verification to N.E.K.O's own scripts/prepare_embedding_model.py. Startup runs this before launcher.py, while PreflightOnly and run_checks.ps1 use verify-only mode so missing or wrong-pinned assets fail closed instead of silently degrading to BM25-only recall.

Live acceptance on 2026-11-21 proved the native worker loaded local-text-retrieval-v1-128d-int8-mlen1024, backfilled all active XiaoYu facts/persona/reflections, and answered a semantic preference query with three vector hits when BM25 scored zero candidates.

## Managed core patches

Ten narrow N.E.K.O patches are currently managed. The first fixes the proactive auto-start idle gate: an internally started text session must not impersonate fresh user activity and block its own proactive delivery. The second exposes the already-native microphone runtime through the active Full Chat toolbar because the compatibility mic control is hidden and the avatar floating control was absent in the live XiaoYu surface. The third keeps Qwen3.8 realtime voice on the provider's reliable server VAD path after live E2E evidence showed semantic VAD could accept audio without emitting speech/transcription events. The fourth publishes the existing native realtime loud-PCM activity signal before the bounded ingress queue so proactive delivery yields to a speaking user even when the worker is backpressured; it does not change provider audio, VAD, DSP, transcripts or queue limits. The fifth preserves the latest requested character during an in-flight avatar switch and force-replays it after completion/failure, preventing rapid A→B→A switching from leaving the backend on A while the frontend avatar was torn down. The sixth is an opt-in whole-reply output gate: it reuses the isolated XiaoYu quiet state and admits or rejects the reply before N.E.K.O splits it into UI text and TTS, making policy-induced "text without voice" impossible while leaving the native text and TTS pipelines intact after admission. The seventh is a generic opt-in first-round provider-native tool-routing bridge: after repeated product probes prove auto-selection unreliable, the private launcher supplies one registered tool name, a conservative regex, and an optional first-round reasoning override. N.E.K.O forwards the provider's normal tool_choice (Qwen3.8 uses reasoning_effort=none for that first forced round) and immediately restores the prior tool/reasoning settings afterward; it does not pre-execute the tool locally and contains no XiaoYu-specific wording. The eighth exposes Alibaba Qwen as a first-class paired clone provider while reusing N.E.K.O's existing voice storage/picker and native Qwen3.8 Omni transport; ordinary TTS/preview use the provider-native Qwen-Audio path and realtime uses the paired Omni clone. The ninth is a unified proactive-interruptibility gate. It reuses N.E.K.O's native ActivitySnapshot and Windows SHQueryUserNotificationState at both planning and final delivery: canned game invitations remain leisure-only (casual_browsing / idle), Windows BUSY/fullscreen/presentation/quiet states hard-veto nonessential delivery, and prepare_proactive_delivery rechecks the latest native snapshot immediately before claim so a game/work transition during generation cannot leak a stale proactive message. Focused work remains interruptible only by the dedicated work-break reminder, whose game-pivot probability stays disabled through native config. It also establishes the first replaceable internal capability path by discovering agent-hidden interruptibility_v1 providers through N.E.K.O's own PluginCatalog/PluginRunner and running them only in background shadow mode; the native verdict remains authoritative. The tenth keeps startup/desktop heavy work off the event loops across main, agent and memory. It reuses N.E.K.O's native TokenTracker, existing background preload pattern, isolated embedded-plugin thread, and pooled internal/external HTTP clients; Python's asyncio.to_thread is used only at blocking first-import/filesystem/config boundaries. A temporary XiaoYu-specific search SSLContext cache was removed after the reuse audit found N.E.K.O already provided the required shared clients. It preserves native storage/network/plugin authorities and adds no second pool, plugin host or cross-request Live2D catalog cache. None introduces a parallel runtime. All are replayed by tools/setup_local.ps1, covered by regression evidence, and should be removed when a future pinned N.E.K.O version includes equivalent behavior.

## Release readiness

tools/run_checks.ps1 ends with a fail-closed release gate. Every case in evals/acceptance_matrix.json must be in a PASS state and point to an existing evidence file. Any case that regresses to pending/deferred/partial/blocked/not-yet-ready blocks the release check.


## Local API cost dashboard

`tools/open_api_cost.cmd` refreshes and opens a local read-only cost report from N.E.K.O's native `config/token_usage.json`. It does not add another usage tracker or call an API. Reference prices and optional daily/monthly warning thresholds live in `tools/api_prices.json`; `null` leaves a threshold disabled.

The bundled rates were rechecked against Alibaba Cloud Model Studio's public pricing pages on 2026-11-20 for the Beijing endpoint used by XiaoYu. They are reference rates rather than an account invoice. The report keeps genuinely unpriced calls separate and uses conservative ranges where N.E.K.O stores less billing detail than the provider: tiered historical aggregates, mixed-modality Realtime input/output tokens, and TTS character counts (N.E.K.O stores Python character length while Bailian bills CJK ideographs as two characters). Provider billing remains authoritative. Budget warnings are informational and never stop requests.


## Frozen architecture direction

The private product direction is frozen by governance/architecture_freeze.json and enforced by tools/check_architecture_freeze.py. N.E.K.O remains the sole companion/runtime authority and its Plugin SDK is the default extension plane. XiaoYu must not grow a second plugin host, model gateway, vector store/memory runtime, agent runtime, HTTP pool, or credential store. External execution belongs behind N.E.K.O's existing external-agent, MCP, or Plugin SDK boundaries. N.E.K.O memory stays authoritative; alternative memory engines may be evaluated only in shadow mode until an explicit promotion decision.

User-visible output is governed by governance/delivery_floor_v1.json. This is a contract, not another runtime. It inventories ordinary replies, proactive output, work-break reminders, game invitations, background-agent results, and QQ outbound delivery under one ALLOW/HOLD/DROP vocabulary. Policy may decide whether output is admissible, but only N.E.K.O native delivery (or its pinned connector path) performs publication. Existing managed patches 0006 and 0009 remain the narrow enforcement adapters for whole-reply admission and proactive final-delivery admission; new core code is not justified merely to make the implementation look more uniform.


### External execution contract

`governance/execution_contract_v1.json` freezes the execution seam without adding another XiaoYu agent framework. One-step work stays on N.E.K.O plugin direct dispatch; multi-step work stays on NekoClaw task agents. Commission state, permissions, capability routing and result outbox remain host-owned. The built-in runtime is the default; N.E.K.O's optional dsh runtime is the only currently approved alternate runtime seam and is host-guarded over ACP. Other external systems are capabilities behind MCP unless N.E.K.O later adds a native runtime adapter. They never become XiaoYu identity, memory, permission, ledger or publication authorities.

This freeze does not enable Agent master or install dsh. Runtime activation remains an explicit product/user configuration choice.


### Plugin autostart admission

`governance/plugin_admission_v1.json` controls only which plugins may become implicit XiaoYu runtime residents. `tools/check_plugin_admission.py` fails closed when an enabled + auto-start plugin is not in the reviewed admission set, and it verifies the pinned QQ checkout against its lock. Native N.E.K.O plugins and the reviewed private interaction-policy plugin keep their existing host lifecycle; no XiaoYu plugin host or permission database is introduced.

This is deliberately **not** a malicious-plugin sandbox. N.E.K.O capability grants and process boundaries remain host-owned, and explicit owner-started/manual-only plugins stay outside this auto-start policy. The admission gate prevents a newly installed third-party plugin from silently becoming a permanent XiaoYu resident; finer-grained hostile-plugin isolation should be reused from a future native N.E.K.O capability boundary rather than emulated in the overlay.

## Reuse-first gate

Every new private runtime plugin or managed N.E.K.O core patch must first have an approved entry in `governance/reuse_reviews.json`. The review records the N.E.K.O native/upstream and mature external candidates considered, supporting evidence, and why reuse alone is insufficient when a thin adapter or private implementation remains. `tools/check_reuse_first.py` is fail-closed and runs inside `tools/run_checks.ps1`; an unreviewed managed patch/plugin or an unmanaged patch file blocks the checks. If a reusable solution later becomes viable, the policy prefers replacing/deleting private code rather than keeping it because it already exists.
