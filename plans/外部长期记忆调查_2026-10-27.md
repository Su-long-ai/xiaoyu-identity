# 外部长期记忆调查（2026-10-27）

## 结论

调查已达到当前决策所需的饱和：继续搜索主要新增的是同类 DSH 插件或云产品，而不是新的评测维度。最重要的结果不是“再挑一个框架”，而是已有 **OmniMemEval** 可作为统一比较层。小鱼应停止自造跨框架 runner，直接写一个 XiaoYu adapter。

## 1. 统一评测层

### OmniMemEval（首选）
- 统一 `add/search/delete` memory backend API。
- 已有多种主流 memory backend adapter，包括 MemOS、Mem0、Zep/Graphiti、Supermemory、EverOS、Letta、Hindsight、Cognee 等。
- 数据：LoCoMo、LongMemEval、BEAM、PersonaMem v2、HaluMem。
- ANSWER/EVAL 使用 OpenAI-compatible模型配置，因此可以把 DeepSeek 作为统一回答/裁判模型。
- 第三方统一复现与厂商自报数字可能差异很大，因此必须复现，不直接引用营销榜单。

来源：
- https://github.com/MemTensor/OmniMemEval
- https://github.com/MemTensor/OmniMemEval/blob/main/docs/user_memory/README.md
- https://github.com/MemTensor/OmniMemEval/blob/main/docs/user_memory/results.md

### Mem0 memory-benchmarks（辅助）
Mem0 自己开源了 LoCoMo / LongMemEval / BEAM harness，适合复核 Mem0 OSS，但不是通用跨框架层。它也明确提醒 embedding、抽取 LLM、judge 和 top-k 会显著改变结果。

来源：https://github.com/mem0ai/memory-benchmarks

## 2. 必须纳入的 benchmark

### LoCoMo
长会话、多跳、时间推理和开放域召回。用于基础长期记忆能力。

### LongMemEval-S
500 题，覆盖 single-session user/assistant/preference、temporal、multi-session、knowledge-update。适合验证更新和跨会话；本身不是中文专项。

### HaluMem
分别评估 Memory Extraction、Memory Updating、Memory QA；适合定位小鱼错误来自语义抽取、状态更新还是最终回答。
来源：https://github.com/MemTensor/HaluMem

### TimlMemBench
中英双语，专门测撤回、替代、作用域、来源、激活与 restraint，并区分 canonical-pool 与 raw-native。应作为小鱼中文/治理型长期记忆的高优先级外部诊断集。
来源：https://aclanthology.org/2026.findings-emnlp.507/

### PersonaMem v2
用于 P3 个性化阶段，不替代基本记忆正确性测试。
来源：https://github.com/bowen-upenn/PersonaMem-v2

### RHELM
Microsoft 的 realistic / heterogeneous / evolving benchmark，包含对话、文件、邮件等多源长期记忆。适合 P4 高阶验证。
来源：https://github.com/microsoft/RHELM

### BEAM
用于超长规模压力。第一阶段只做 100K smoke，避免方案尚未稳定时烧大量 API。

## 3. 第一批框架候选

- **MemOS**：DSH 原生接入价值高，另做插件级比较。
- **Mem0 OSS**：成熟自托管 memory layer；托管版单独标注。
- **Hindsight**：时间推理与超长历史方向。
- **EverOS / EverMemOS**：本地优先、可审计，也有 DSH 接入。
- **Graphiti**：显式时间有效期、provenance、fact invalidation，正面对应 T15。
- **Cognee**：知识图 + 向量、自托管，已有统一 adapter。
- **Letta**：更偏完整 stateful agent/runtime，放到 agent-level 比较而不是纯 memory backend 算法榜。

## 4. DSH 原生生态

除 MemOS/EverOS 外，社区已有多种 Markdown/SQLite/FTS/BM25/语义召回/冲突/作用域/人审晋升插件。它们说明小鱼在作用域、FTS、Git、人审、冲突、自动总结等方向很容易重复造轮子。第一批不必全部部署，只用于复用审计和插件级 benchmark。

代表：
- https://github.com/kovey/dsh-memory
- https://github.com/LZMW/dsh-memory
- https://github.com/x-000001/dsh-memory-plugin
- https://github.com/kiefeng/dsh-lan-memory

## 5. DeepSeek 条件

小鱼本机已配置 `DEEPSEEK_API_KEY` 和 `deepseek-flash`。真实付费 benchmark 前必须先设置项目级硬预算、记录 token/费用和失败重试次数。

## 6. 公平比较协议

### A. 模型受控 / self-hosted
同一数据、同一 ANSWER/EVAL DeepSeek 模型、同一温度/思考模式、同一 top-k 或上下文 token 上限、同一评分器。能统一 extraction LLM 和 embedding 时也统一；不能统一必须显式标记。

首批：XiaoYu V2、Mem0 OSS、Graphiti、Hindsight、EverOS、Cognee。

### B. As-shipped / 产品整体
云端服务可使用其内部专有 extraction/rerank/index，只统一下游回答与 judge。结果表示产品整体效果，不能用于证明某个算法优越。

### C. DSH agent-level
比较：无插件、MemOS DSH、EverOS DSH、再选 1 个社区插件，以及小鱼未来 DSH 插件。

## 7. 停止调查条件

当前已经满足：
1. 找到通用跨后端 harness；
2. 找到覆盖 recall/update/hallucination/personalization/governance/scale 的 benchmark 组合；
3. 找到至少 5 个可自托管候选；
4. 找到 DSH 原生现成实现；
5. 找到 DeepSeek 兼容路径；
6. 继续搜索主要只增加同类插件，而不是新的能力维度。

因此外部调查从“继续罗列项目”切换为“真实部署、统一 adapter、跑数据”。只有出现当前候选完全没有的新能力或独立高质量 benchmark，才重新扩展调查池。
